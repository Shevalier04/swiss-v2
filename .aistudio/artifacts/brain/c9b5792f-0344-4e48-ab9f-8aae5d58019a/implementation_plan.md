# 手机浏览器通知权限拦截解除指引与一键重检实施方案

## 用户需求与背景分析
用户在手机端使用“掌上课表”点击开启通知或测试通知时，由于手机浏览器（如华为浏览器、Chrome 移动版、iOS Safari 或微信内置浏览器）之前已将通知权限记录为“拒绝/拦截（denied）”，导致再次点击时无法弹出原生授权框，且系统直接报错或提示未授权。
根据用户确认的方案：
> **核心决策**：弹出全平台主流手机浏览器解除拦截图文指引弹窗，并提供一键重新检测与权限恢复功能。

---

## 架构与核心功能设计

### 1. 常见移动浏览器通知拦截机制剖析
- **Web 规范限制**：当浏览器网站权限被设为 `denied`（拒绝）后，前端调用 `Notification.requestPermission()` 不会再弹出任何系统授权浮窗，直接 Promise resolve 为 `denied`。
- **用户困境**：普通学生用户不知道如何进入手机浏览器深层设置中解除站点权限拦截。
- **解决方案**：提供针对具体浏览器分类的交互式操作指南，并提供自动重新读取 `Notification.permission` 的一键检测机制。

```
┌─────────────────────────────────────────────────────────────┐
│ 用户点击“开启系统通知” / “开启锁屏推送” / 开启通道开关      │
└──────────────────────────────┬──────────────────────────────┘
                               │
               ┌───────────────┴───────────────┐
               ▼                               ▼
       权限状态 !== 'denied'          权限状态 === 'denied'
               │                               │
    正常调用 requestPermission()       ▼ 自动弹出
               │                    ┌─────────────────────────┐
      用户点击允许/拒绝             │ 解除通知拦截指引弹窗    │
               │                    │ 包含：分类标签页引导   │
         成功开启通知               │ +【一键重新检测】按钮   │
                                    └────────────┬────────────┘
                                                 │
                                         用户在设置中允许后点击
                                                 ▼
                                     自动同步 settings.sys=true
                                       立即生效并发送测试通知
```

## 模块改造详细方案

### 1. 新增全浏览器解除拦截引导组件 `src/components/NotificationGuideModal.tsx`
设计美观、符合 Swiss Editorial 与极简高品质风格的弹窗，支持分类切换：
- **华为浏览器 / 鸿蒙系统 (Huawei Browser & HarmonyOS)**：
  - 路径 1（快捷方式）：点击地址栏左侧或右侧的「锁头🔒 / 盾牌」小图标 ➔ 点击「网站设置」/「权限管理」➔ 将「通知」修改为【允许】。
  - 路径 2（系统设置）：手机【设置】➔【应用和服务】➔【应用管理】➔【华为浏览器】➔【通知管理】➔ 打开【允许通知】。
  - 路径 3（添加桌面）：点击浏览器底部菜单【添加到桌面】，以 PWA 独立窗口常驻运行。
- **Chrome / Edge 手机版 (Chrome / Edge Mobile)**：
  - 路径 1：点击网址栏左侧的「页面信息 🎚️」或「锁头 🔒」➔ 点击「权限」➔ 开启「通知」开关。
  - 路径 2：右上角【三点菜单】➔【设置】➔【网站设置】➔【通知】➔ 找到当前网站设为【允许】。
- **iOS Safari (iPhone / iPad)**：
  - 说明：苹果 iOS 必须先添加到主屏幕才能开启系统通知。
  - 操作：点击 Safari 底部居中【分享图标 📤】➔ 选择【添加到主屏幕 ➕】➔ 打开桌面图标即可正常弹窗开启通知。
- **微信 / QQ / 国产其他浏览器 (Quark, UC, 小米, OPPO, vivo)**：
  - 微信/QQ：右上角【···】➔ 选择【在浏览器中打开】（推荐 Chrome 或 Edge）。
  - 小米/OPPO/vivo：点击地址栏安全盾牌/设置 ➔ 网站权限 ➔ 通知设为允许。

### 2. 增强 `src/utils/pushManager.ts`
- 新增 `recheckNotificationPermission()` 函数：
  - 重新读取 `Notification.permission`；
  - 重新检测 `getActiveServiceWorker()` 与 `getCurrentPushSubscription()`；
  - 返回最新权限等级与中文诊断报告。
- 优化错误提示：
  - 当订阅或请求权限返回 `denied` 时，返回统一的拦截标志位 `isBlocked: true`，便于 UI 自动唤起指引弹窗。

### 3. 改造 `src/components/ReminderTab.tsx`
- 状态提升与响应式监听：
  - 引入 `showUnblockModal` 状态及当前触发源（推送/本地通知）；
  - 在 `handleTogglePush`、`handleRequestLocalPermission`、以及通道开关 `sys` 点击时，一旦状态为 `denied`，自动打开 `NotificationGuideModal`；
  - 在弹窗与状态面板中加入常驻提示标签：“权限受限？查看各浏览器解除拦截指引”；
  - 在弹窗内点击【一键重新检测】：
    - 检测成功变更为 `granted` 时，自动执行开启流程，toast 弹窗“🎉 通知权限已恢复！系统已为您自动激活通知功能”，并关闭弹窗；
    - 若仍为 `denied`，高亮当前步骤引导，并友好提示“当前仍被浏览器阻止，请确认已勾选‘允许’”。

## 验证与测试计划
1. **编译与类型安全验证**：
   - 运行 `compile_applet` 确保 TypeScript 无编译与类型错误。
2. **场景模拟验证**：
   - 模拟 `Notification.permission === 'denied'` 场景：
     - 点击“开启系统通知权限”或“开启锁屏推送”，确认能自动弹出全浏览器解除拦截弹窗；
     - 切换不同浏览器 Tab（华为、Chrome/Edge、iOS Safari、微信/其他），核对每个指引的完整性与准确性；
     - 点击【一键重新检测】，确认状态判断准确、反馈明确；
   - 模拟权限允许后的一键重检激活流程，验证自动触发通知与设置保存。
